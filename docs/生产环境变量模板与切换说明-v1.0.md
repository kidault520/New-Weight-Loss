# 生产环境变量模板与切换说明 v1.0

## 目标

- 开发阶段继续 `dev_simulation` 可跑通。
- 上线前切到 `production_strict` 时，可通过统一模板逐项补齐配置。
- 用同一套 `preflight` 脚本做门禁，不靠人工记忆。

---

## 新增模板文件

- `server/.env.production.template`
  - 这是生产配置模板，不直接用于本地开发。
  - `__REQUIRED__` 表示必须替换为真实值，否则 `predeploy:check` 会继续报错。
  - `__OPTIONAL__` 表示当前能力可选（按业务是否启用决定）。

---

## 本地开发（保持不变）

- 使用：`server/.env`
- 推荐值：
  - `APP_RUNTIME_MODE=dev_simulation`
  - `ALLOW_SIMULATED_PAYMENT=true`
  - `ALLOW_SIMULATED_DELIVERY=true`
  - `ALLOW_SIMULATED_SMS=true`
  - `SMS_PROVIDER/PAYMENT_PROVIDER/DELIVERY_PROVIDER=mock`

---

## 上线前切换步骤（建议）

1. 复制模板：
   - 从 `server/.env.production.template` 复制一份到部署环境变量中心或机密管理系统。
2. 替换必填项：
   - Supabase：`VITE_SUPABASE_URL`、`VITE_SUPABASE_ANON_KEY`、`SUPABASE_SERVICE_ROLE_KEY`
   - 支付：`PAYMENT_CREATE_WEBHOOK_URL`、`PAYMENT_WEBHOOK_TOKEN`、`PAYMENT_CALLBACK_TOKEN`
   - 配送：`DELIVERY_CREATE_WEBHOOK_URL`、`DELIVERY_WEBHOOK_TOKEN`、`DELIVERY_CALLBACK_TOKEN`
   - 短信：`SMS_WEBHOOK_URL`、`SMS_WEBHOOK_TOKEN`
3. 确认严格模式开关：
   - `APP_RUNTIME_MODE=production_strict`
   - `ALLOW_SIMULATED_PAYMENT=false`
   - `ALLOW_SIMULATED_DELIVERY=false`
   - `ALLOW_SIMULATED_SMS=false`
4. 执行门禁：
   - `npm run predeploy:check`
   - 若有红项，禁止发布；清零后再发布。

---

## 定向校验命令（可选）

可用 `--env-file` 指定检查某份环境文件（不会覆盖你的本地开发文件）：

```bash
node scripts/preflight-readiness.cjs --strict --env-file=server/.env.production.template
```

说明：
- 该命令会把 `__REQUIRED__` / `your_xxx` / `placeholder` 视为“未配置”。
- 目的不是“刷绿”，而是防止占位值误过门禁。

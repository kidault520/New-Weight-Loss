# 用户餐食与补剂展示同步治理说明（v1.0）

## 1. 文档目的

用于统一用户端餐食与补剂在多入口展示的一致性口径，减少“同一时刻不同页面显示不一致”的问题。

- 保证首页、聊天、详情页展示同一份有效数据
- 保证“今天/明天/本周”时间分桶一致（北京时间）
- 保证餐食排期与补剂阶段在订单状态变化时同步更新

---

## 2. 适用范围

- 用户端：首页卡片、聊天卡片、详情页
- 后端：餐食排期查询、补剂阶段查询
- 数据层：`delivery_schedules`、补剂阶段相关表、`orders`

---

## 3. 核心实体与单一真相

### 3.1 核心实体

- 餐食执行：`delivery_schedules`（`delivery_type = meal`）
- 补剂执行：补剂阶段与阶段条目（排班+阶段组合）
- 订单约束：`orders`（支付状态、服务状态）

### 3.2 单一真相（SoT）

- 餐食展示以 `delivery_schedules` 为准
- 补剂展示以“当前阶段计算结果”与阶段条目为准
- 订单有效性以 `orders` 为准，决定是否允许展示执行内容

---

## 4. 展示同步规则（必须遵守）

1. **统一时区**
   - 所有“日期分桶/当天判断”统一按北京时间计算。

2. **统一查询窗口**
   - “今天/明天/本周”在首页、聊天、详情使用同一日期边界规则。

3. **统一入口行为**
   - 同一用户同一时刻，不同入口展示的餐食与补剂状态必须一致。

4. **订单约束一致**
   - 无有效订单：显示不可执行提示，不展示伪执行数据。
   - 有效订单且服务进行中：展示对应执行数据。

5. **刷新策略一致**
   - 主动操作后必须触发统一 Query Key 失效与刷新。
   - 被动展示场景允许短轮询，但需避免不同入口刷新频率导致明显漂移。

---

## 5. 常见不一致场景与处理

1. **首页有餐食，聊天无餐食**
   - 优先检查：两侧查询日期参数是否一致（北京时间 key）。

2. **补剂阶段切换日显示错卡**
   - 优先检查：阶段起始日来源与当天计算逻辑是否统一。

3. **订单已开启服务，补剂仍提示暂无计划**
   - 优先检查：订单状态筛选条件是否与餐食侧一致。

4. **操作后只有当前页更新，其他入口仍旧数据**
   - 优先检查：统一 Query Key 是否全部失效。

---

## 6. 最小回归包（建议每次发版执行）

1. 同一账号同一时刻对比：首页 / 聊天 / 详情（餐食）
2. 同一账号同一时刻对比：首页 / 聊天 / 详情（补剂）
3. 北京时间边界（23:50、00:10）各验证一次
4. 有效订单未配置、已配置、服务中、已结束各验证一次
5. 单餐修改后，三入口是否 10 秒内一致

---

## 7. 观测与巡检

- 使用 `docs/meal-supplement-sync-smoke-check.sql` 做只读巡检
- 重点看：
  - 时间边界分布是否异常
  - 订单有效用户与展示数据是否匹配
  - 同一用户今天是否存在缺餐/异常阶段

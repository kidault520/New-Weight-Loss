# 配送计划与配送地址治理说明（v1.1）

## 1. 文档目的

本版本用于对齐「验收清单文本」与「当前已落地代码」之间的口径，作为最终联调与回归基准。

- 统一数据口径：执行主表为 `delivery_schedules`
- 统一流程口径：入口、配置、改单餐、回调、后台管理使用同一套规则
- 统一验收口径：按“已实现 / 部分实现 / 待增强”标记，避免误判

---

## 2. 当前生效范围（代码事实）

### 2.1 核心实体

- `delivery_addresses`：地址主数据
- `delivery_schedules`：配送执行主数据（餐次、状态、锁定、地址快照）
- `orders`：订单与服务状态
- `delivery_callback_events`：回调事件与幂等/冲突追踪

### 2.2 核心规则（已生效）

- 地址归属：服务层校验 + RLS 双保险（地址必须属于当前用户且未删除）
- 状态机：`pending/scheduled/preparing/shipped/delivered/cancelled`
- 回调防回退：终态不可改回，非终态不允许回退
- 回调歧义保护：`external_order_id` 多命中时拒绝更新
- 统计口径：按北京时间日期边界

---

## 3. 与 v1.0 的关键差异（本次修订）

1. **表名口径修正**
   - 历史文案中的 `meal_delivery_schedules` 统一改为 `delivery_schedules`。

2. **地址安全规则升级**
   - 新增地址归属 RLS 约束，防止跨用户地址写入。

3. **回调稳定性升级**
   - 新增 `external_order_id` 唯一守护；
   - 回调侧增加歧义拒绝与 `status_conflict` 事件记录。

4. **失败可见性升级**
   - 配置完成主链路已阻断“同步不完整仍成功收口”；
   - 但聊天卡片改单餐链路仍有部分失败仅日志提示（见第 6 节）。

---

## 4. 端到端流程（当前标准）

### 4.1 入口与返回路径

- 我的 > 我的配送计划：无有效订单拦截；关闭回我的页
- 订单入口（开启服务）：完成后订单状态与计划同步
- 瑞丹维入口：复用同一套配送计划逻辑
- 聊天配送卡片：可改单餐，交互与计划页保持一致

### 4.2 首次配置

日期选择 -> 地址确认 -> 生成配送计划 -> 确认生效 -> 提示后跳转

### 4.3 单餐修改

改地址 -> “确认” -> “锁定中” -> 2 秒自动锁定 -> 写入 `delivery_schedules`

### 4.4 地址管理

- 在用地址删除：直接拦截
- 编辑在用地址：先提示影响范围，再允许继续
- 锁定窗口：今日且进入配送前 1 小时，禁止修改

## 5. 验收矩阵（v1.1）

### 5.1 已实现（可作为上线基线）

- 入口守卫（无订单拦截）与返回路径
- 首次配置与已配置分流
- 单餐 2 秒自动锁定
- 删除在用地址拦截与滑动回正
- 后台状态流转守卫（含终态保护）
- 回调映射优先级与防回退
- 北京时间统计口径
- 管理端搜索分页一致性
- 聊天卡片改单餐失败可见提示
- 后台逐条记录展示“状态更新时间/最后回调时间”
- SQL 巡检脚本固化（`docs/delivery-regression-smoke-check.sql`）

### 5.2 部分实现（需知晓现状）

- 状态来源时间当前以“状态更新时间 + 最后回调时间”为主；若需区分“人工改状态/回调改状态”的精确来源类型，仍可后续增强

### 5.3 待增强（非阻断）

- 自动化执行入口（CI 定时任务）可后续补充；当前已提供固定 SQL 脚本供人工一键巡检

---

## 6. 文档与现状差异说明（供测试/运营）

1. 删除在用地址的文案为动态文案（含“约 N 个餐次”），不固定为单一句式。
2. 状态展示当前支持逐条“状态更新时间 + 最后回调时间”；页面“最近刷新时间”继续保留为辅助信息。

---

## 7. 最小回归包（建议每次发版执行）

1. 无订单点击 3 个入口（我的/瑞丹维/聊天）
2. 有订单未配置：完整生成一次
3. 已配置改单餐（已有地址）一次
4. 已配置改单餐（新增地址）一次
5. 编辑地址标签一次
6. 编辑联系人/电话/详细地址一次
7. 删除在用地址一次
8. 删除未用地址一次
9. 管理端状态前进 + 回退拦截一次
10. 跑 SQL 巡检脚本并留档

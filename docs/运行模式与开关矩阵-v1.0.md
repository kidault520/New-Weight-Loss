# 运行模式与开关矩阵 v1.0

## 目标

在不改业务入口的前提下，实现：
- 开发环境可完整联调（允许模拟）
- 生产环境可严格收口（禁止高风险模拟）

## 运行模式

- `APP_RUNTIME_MODE=dev_simulation`
  - 默认（当 `NODE_ENV!=production` 且未显式设置时）
  - 允许模拟能力用于链路测试
- `APP_RUNTIME_MODE=production_strict`
  - 默认（当 `NODE_ENV=production` 且未显式设置时）
  - 禁止高风险模拟能力

## 开关定义

- `ALLOW_SIMULATED_PAYMENT`：是否允许模拟支付能力
- `ALLOW_SIMULATED_DELIVERY`：是否允许模拟配送能力
- `ALLOW_SIMULATED_SMS`：是否允许模拟短信能力

> 规则：未显式配置时，`dev_simulation` 默认 `true`，`production_strict` 默认 `false`。

## 配置矩阵

| 项 | dev_simulation | production_strict |
|---|---|---|
| `ALLOW_SIMULATED_PAYMENT` | 建议 `true` | 必须 `false` |
| `ALLOW_SIMULATED_DELIVERY` | 建议 `true` | 必须 `false` |
| `ALLOW_SIMULATED_SMS` | 建议 `true` | 必须 `false` |
| `SMS_PROVIDER` | `mock/webhook` 均可 | 需真实通道（建议 `webhook`） |
| `PAYMENT_PROVIDER` | 可 `mock` | 禁止 `mock` |
| `DELIVERY_PROVIDER` | 可 `mock` | 禁止 `mock` |
| `PAYMENT_CALLBACK_TOKEN` | 建议配置 | 必须配置 |
| `DELIVERY_CALLBACK_TOKEN` | 建议配置 | 必须配置 |

## Preflight 命令

- 本地预检：`npm run preflight`
- JSON 输出：`npm run preflight:json`
- 发布前严格预检：`npm run predeploy:check`

严格预检规则：
- 在 `--strict` 模式下存在红项（`red`）即返回非 0，阻断发布。

## 推荐环境示例

### 开发环境

```env
APP_RUNTIME_MODE=dev_simulation
ALLOW_SIMULATED_PAYMENT=true
ALLOW_SIMULATED_DELIVERY=true
ALLOW_SIMULATED_SMS=true
SMS_PROVIDER=mock
PAYMENT_PROVIDER=mock
DELIVERY_PROVIDER=mock
```

### 生产环境

```env
APP_RUNTIME_MODE=production_strict
ALLOW_SIMULATED_PAYMENT=false
ALLOW_SIMULATED_DELIVERY=false
ALLOW_SIMULATED_SMS=false
SMS_PROVIDER=webhook
PAYMENT_PROVIDER=webhook
DELIVERY_PROVIDER=webhook
PAYMENT_CALLBACK_TOKEN=***
DELIVERY_CALLBACK_TOKEN=***
```

## 注意事项

1. `preflight` 是阶段1骨架，当前以配置与明显高风险项检查为主。
2. 阶段2将把更多“业务主链路已接入”的校验加入阻断规则。
3. 即使集成中心显示“可测”，仍需以 `predeploy:check` 和主链路回放结果作为上线依据。

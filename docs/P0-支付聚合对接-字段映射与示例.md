# P0：支付聚合对接（字段约定与示例）

面向：**支付聚合平台**（微信/支付宝等由平台承接）。本系统**不**以直连单家支付公司为默认路径。

相关代码：

- 主动创建支付单（出站 HTTP）：`server/services/paymentProviderService.js`（`PAYMENT_PROVIDER=webhook` 或 `aggregator`）
- 支付结果回调（入站）：`server/routes/orders.js` → `POST /api/orders/payment/callback`
- 状态机：`server/utils/orderPaymentTransition.js`

---

## 1. 环境变量（生产最小集）

| 变量 | 说明 |
|------|------|
| `PAYMENT_PROVIDER` | 使用聚合时设为 `webhook` 或 `aggregator`（与 `webhook` 等价） |
| `PAYMENT_CREATE_WEBHOOK_URL` | 聚合平台提供的「创建支付单」HTTPS 地址（由你们服务端 POST） |
| `PAYMENT_WEBHOOK_TOKEN` | 可选；若配置则出站请求带 `Authorization: Bearer <token>` |
| `PAYMENT_CALLBACK_TOKEN` | **必填**；聚合平台（或你们的网关）回调本系统时，请求头需携带同名令牌 |
| `INTERNAL_API_BASE_URL` | 可选；集成中心等服务自测内调 API 时使用 |

`PAYMENT_CALLBACK_TOKEN` 对应请求头名称：**`x-payment-callback-token`**（全小写）。

---

## 2. 出站：创建支付单（本系统 → 聚合）

本系统在 `webhook` 模式下将 **业务侧传入的 JSON 原样 POST** 到 `PAYMENT_CREATE_WEBHOOK_URL`（`Content-Type: application/json`）。

**本系统侧不强制聚合商字段名**，由你们在业务代码或 BFF 中组好聚合商要求的 body。联调/集成中心「主动下发」测试时，建议至少包含下列**语义**（字段名可与下表不同，由聚合文档为准）：

| 语义 | 建议字段名（示例） | 说明 |
|------|-------------------|------|
| 商户订单号 | `order_number` | **必须能对应**库表 `orders.order_number`，回调里的 `external_order_id` 与此一致 |
| 金额 | `amount`（元）或 `amount_cents`（分） | 仅直连微信适配器会解析；聚合 URL 若需其它字段名，请在出站 payload 中按文档改名 |
| 商品描述 | `description` | 可选 |
| 回调通知 URL | 由聚合后台配置 | 聚合成功后应通知到你们的**网关或转发服务**，再转换为第 3 节格式调用本系统 |

---

## 3. 入站：支付结果回调（聚合 → 本系统）

**URL（相对你们 API 根路径）**

```http
POST /api/orders/payment/callback
```

**请求头**

| 头 | 必填 | 说明 |
|----|------|------|
| `Content-Type` | 是 | `application/json` |
| `x-payment-callback-token` | 是 | 与 `PAYMENT_CALLBACK_TOKEN` 完全一致 |

**Body 字段**

| 字段 | 必填 | 说明 |
|------|------|------|
| `payment_event_id` | 是 | **幂等键**；同一 ID 重复投递返回 200 且 `deduplicated: true`，不重复改单 |
| `external_order_id` | 是 | 对应 `orders.order_number` |
| `payment_status` | 是 | 小写；允许值：`pending` / `paid` / `refunded` / `cancelled`（见 `orderPaymentTransition.js`） |
| `paid_at` | 否 | ISO 8601 字符串；`paid` 时建议传实际支付时间 |
| `raw_payload` | 否 | 对象；不传则整份 `body` 会写入 `payment_callback_events.payload` |

**成功（首次处理）**  
HTTP 200，body 含 `success: true`（具体字段以实现为准）。

**幂等（重复 `payment_event_id`）**  
HTTP 200，示例：

```json
{
  "success": true,
  "deduplicated": true,
  "code": "PAYMENT_EVENT_DUPLICATE",
  "message": "Duplicate callback ignored"
}
```

**支付成功（示例 body，供聚合网关转发时对照）**

```json
{
  "payment_event_id": "agg-pay-20260325-001",
  "external_order_id": "ORD202603250001",
  "payment_status": "paid",
  "paid_at": "2026-03-25T10:00:00.000Z",
  "raw_payload": {
    "channel": "aggregate_xxx",
    "third_party_trade_no": "4200000000xxxx"
  }
}
```

**常见错误码（节选）**

| HTTP | code | 含义 |
|------|------|------|
| 401 | PAYMENT_CALLBACK_UNAUTHORIZED | 令牌错误或未带 |
| 400 | PAYMENT_CALLBACK_INVALID_PAYLOAD | 缺必填字段 |
| 404 | ORDER_NOT_FOUND | `external_order_id` 找不到订单 |
| 409 | ORDER_STATE_CONFLICT | 当前订单支付状态不允许过渡到目标状态 |

## 4. 聚合侧落地检查清单

- [ ] 聚合后台「服务器通知 URL」指向可公网访问的 HTTPS（或经 API 网关转发到上述 path）
- [ ] 转发层把聚合报文映射为第 3 节字段，并注入 **`x-payment-callback-token`**
- [ ] `payment_event_id` 使用聚合侧唯一事件 ID（或 `平台订单号+事件类型`），避免重复推送导致重复记账
- [ ] 沙箱订单的 `external_order_id` 与库里 `order_number` 一致
- [ ] 生产关闭 `PAYMENT_PROVIDER=mock`，使用 `webhook`/`aggregator`

---

## 5. 与「直连微信」的关系

`PAYMENT_PROVIDER=wechat_pay` 为**备选联调**，不是聚合主路径。生产默认应使用本节 **webhook + 回调** 形态。

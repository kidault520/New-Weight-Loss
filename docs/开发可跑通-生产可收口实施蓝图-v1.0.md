# 开发可跑通 + 生产可收口实施蓝图 v1.2

## 1. 背景与目标

当前处于开发阶段，部分三方平台（短信、支付、配送、设备、合同）尚未完全接通。  
本蓝图目标是同时满足两件事：

1. **开发阶段可完整跑通业务链路**（即使三方未接通）
2. **上线阶段可一键阻断高风险配置**（避免带病上线）

核心原则：**同一路由、双模式运行、自动化闸门**。

---

## 2. 设计原则

1. **同一路由，不分叉两套业务逻辑**
   - 业务入口保持一致
   - 通过 provider adapter 切换 mock / real

2. **开发可模拟，生产必严格**
   - 开发模式允许模拟器接管外部依赖
   - 生产模式默认拒绝 mock fallback

3. **文档与脚本同源**
   - 人看清单 + 机器校验规则同源维护
   - 避免“文档说一套，系统跑一套”

---

## 3. 三阶段实施计划（不改核心业务先加护栏）

## 阶段 1：双模式与配置护栏骨架（1~2 天）

### 目标

- 建立清晰、可执行的运行模式边界。

### 动作

1. 定义运行模式：
   - `APP_RUNTIME_MODE=dev_simulation|production_strict`
2. 定义高风险开关：
   - `ALLOW_SIMULATED_PAYMENT`
   - `ALLOW_SIMULATED_DELIVERY`
   - `ALLOW_SIMULATED_SMS`
3. 建立统一配置读取层（避免散落 `process.env` 直接读取）。

### 产物

- 运行模式与开关矩阵文档
- 统一配置 schema（字段、默认值、环境约束）

### 验收

- `dev_simulation` 下主链路可跑通
- `production_strict` 下模拟能力被硬禁用

---

## 阶段 2：Readiness Gate（2~3 天）

### 目标

- 启动前/部署前自动识别并阻断“上线前必修清单”风险。

### 动作

1. 新增预检脚本：
   - `scripts/preflight-readiness.(js|ts)`
2. 覆盖关键检查项：
   - 短信 provider 与 webhook 配置
   - 支付/配送 provider 与回调 token
   - 模拟支付接口生产禁用
   - Edge 鉴权写法一致性
3. 输出分级结果：
   - 红（阻断）
   - 黄（高风险）
   - 绿（通过）

### 产物

- `npm run preflight`（本地）
- `npm run predeploy:check`（发布前）
- Readiness 规则文档

### 验收

- 缺关键配置返回非 0 并阻断
- 命中生产高危项（如模拟支付可用）直接失败

---

## 阶段 3：可回放端到端模拟链路（2~3 天）

### 目标

- 在三方未接通期间，仍可稳定回归主链路。

### 动作

1. 建立固定场景回放脚本：
   - 注册/验证码
   - 下单/支付
   - 配送状态推进
   - AI 问答
2. 引入 deterministic mock（固定输入固定输出）
3. 输出回放报告（通过率、失败点、日志定位）

### 产物

- `npm run smoke:e2e:sim`
- 开发环境链路回放手册

### 验收

- 一键跑完核心链路
- 结果可重复、失败可追踪

---

## 4. 运行模式矩阵（建议）

| 能力 | dev_simulation | production_strict |
|---|---|---|
| 短信验证码 | mock/webhook 均可 | 仅 webhook/真实通道 |
| 支付创建 | 可模拟 | 禁止模拟，必须真实创建 |
| 支付确认 | 可测试接口 | 禁止模拟确认接口 |
| 配送下发 | 可模拟 | 禁止模拟，必须真实下发 |
| 设备同步 | 可占位模拟 | 必须真实 provider 或显式关闭能力 |
| 合同/电子签 | 可占位流程 | 必须真实接入或显式关闭入口 |

---

## 5. 与“上线前必修清单”映射关系

- P0/P1 清单是“**要解决什么**”
- 本蓝图是“**怎么组织解决**”
- 建议执行路径：
  1. 先落地阶段 1/2（护栏先行）
  2. 再逐条消化 P0/P1 业务项
  3. 最后用阶段 3 回放做整体验收

## 8. 风险控制与边界

1. 不允许“生产环境默认 fallback 到 mock”
2. 不允许“文档要求”与“脚本检查”脱节
3. 不允许“集成中心可测”替代“主业务入口已接通”的验收标准

# 产品配置管理规范 v1.0

## 1. 目的与范围

本规范用于统一 B 端「产品配置管理」的行为口径，覆盖以下模块：

- 品类与属性配置
- 折算率配置
- 商品同步与映射
- 版本发布与历史记录
- 订单使用后的锁定规则

目标是确保：

- 业务操作可追溯（版本可回放、历史可解释）
- 已被订单使用的数据不可被破坏
- 草稿与正式发布严格分离
- 佣金计算口径稳定、无歧义

---

## 2. 核心原则

### 2.1 草稿与发布分离

- 在「发布版本」前，所有改动仅为草稿（前端本地态），不写服务端、不写历史。
- 只有点击「发布版本」后，才会：
  - 写入 `sales_product_config`
  - 追加 `sales_product_config_versions` 快照
  - 写入 `admin_change_audit_logs` 历史记录

### 2.2 历史不可歧义

- 历史记录应表达真实业务语义：
  - 新增属性写为「新增属性：品类/属性」
  - 新增折算率写为「新增折算率：品类/属性 = xx%」
- 备注必须可见，展示优先级：
  1. `after_data.note`
  2. `reason`

### 2.3 在用数据保护

- 只要某字段已被生效订单使用，必须锁定：
  - 不可编辑
  - 不可删除
- 锁定粒度优先字段级（属性、折算率、商品映射），避免粗暴整行锁死。

### 2.4 折算率计算口径唯一

- 当某品类存在属性明细折算率时，该品类基础折算率视为失效，不参与计算。
- 计算优先级：
  1. 属性明细折算率
  2. （仅当无属性明细模式时）品类基础折算率
  3. 默认折算率兜底（`0.6`）

---

## 3. 页面流程规范

## 3.1 两步发布流程（currentOnly 模式）

### Step 1：品类与折算率

- 底部仅显示：`取消` + `下一步`
- 不显示版本标识输入框
- 允许进行草稿编辑

### Step 2：商品同步

- 底部显示：`版本标识（必填）` + `取消` + `发布版本`
- 点击发布时执行正式提交

### Step 3：历史查看

- 「配置历史记录」顶部必须显示：
  - 版本号
  - 生效时间
  - 当前版本备注（若有）

---

## 4. 锁定规则规范

## 4.1 锁定数据来源

优先使用接口：

- `GET /api/admin/sales-product-config/usage-locks`

返回至少包含：

- `usedCategoryKeys`
- `usedAttributeKeys`
- `usedRateKeys`
- `usedMappingKeys`

降级方案：

- 若接口失败，允许用版本数据推导锁定集合（best effort），但不得误放开已用字段。

## 4.2 前端交互要求

- 列表可进入编辑弹窗（不要求先整行禁用）
- 弹窗中已锁字段置灰并禁用控件
- 商品同步中已锁映射的编辑/删除按钮置灰
- Tooltip 要明确说明「已被生效订单使用，禁止修改/删除」

---

## 5. 历史记录规范

## 5.1 仅记录正式动作

历史接口 `GET /versions/history` 仅返回：

- `publish`
- `delete_version`

不记录草稿保存行为。

## 5.2 文案规范

- 版本变更：`版本: vX -> vY（备注：xxx）`
- 属性新增：`新增属性：品类/属性`
- 折算率新增：`新增折算率：品类/属性 = xx%`
- 商品映射新增：`新增商品映射：商品 -> 品类/属性`

---

## 6. 版本规范

## 6.1 版本号规则

- 展示版本号连续化（v1/v2/v3...）
- 数据库版本号也应保持连续，避免历史对齐混乱

## 6.2 快照规则

- 快照必须来自发布时的真实内容
- 不允许在查询阶段对历史快照做破坏性重写
- 快照异常应优先修数据源（迁移修复），而非仅 UI 映射

---

## 7. 发布校验规范

发布时必须满足：

- `publishVersion=true`
- `note`（版本标识）非空
- 不存在已被订单使用字段的修改/删除操作

建议错误码：

- `VALIDATION_ERROR`
- `CONFIG_ENTITY_IN_USE`
- `DRAFT_LOCAL_ONLY`

---

## 8. 验收清单

每次发布前后最少验证以下场景：

- 草稿改动不写历史
- 发布后新增版本且历史可见
- 备注在历史卡片和标题区可见
- 已锁属性/折算率/映射不可编辑或删除
- 存在属性明细时基础折算率失效
- 佣金计算使用的折算率与页面规则一致

---

## 9. 变更管理建议

- 涉及版本与快照的调整必须配套 SQL migration
- 涉及口径变更（如折算率优先级）必须同步：
  - 前端展示逻辑
  - 后端计算逻辑
  - 历史文案逻辑
- 每次改动后保留 1 份回归记录（截图 + API 返回示例）

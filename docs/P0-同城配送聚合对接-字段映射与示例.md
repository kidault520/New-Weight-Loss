# P0：同城配送聚合对接（字段约定与示例）

面向：**同城配送聚合平台**（运力由平台调度）。本系统**不**以直连单家快递公司官方接口为默认路径。

相关代码：

- 主动下发运力（出站 HTTP）：`server/services/deliveryProviderService.js`（`DELIVERY_PROVIDER=webhook` 或 `aggregator`）
- 配送状态回调（入站）：`server/routes/deliveryCallbacks.js` → `POST /api/delivery-callbacks/status`
- 状态映射：`server/config/deliveryStatusMapping.js`
- 状态机：`server/utils/deliveryStatusTransition.js`

---

## 1. 环境变量（生产最小集）

| 变量 | 说明 |
|------|------|
| `DELIVERY_PROVIDER` | 使用聚合时设为 `webhook` 或 `aggregator` |
| `DELIVERY_CREATE_WEBHOOK_URL` | 聚合平台提供的「创建配送单」HTTPS 地址 |
| `DELIVERY_WEBHOOK_TOKEN` | 可选；出站 `Authorization: Bearer <token>` |
| `DELIVERY_CALLBACK_TOKEN` | **必填**；回调本系统时请求头携带同名令牌 |

回调请求头名称：**`x-delivery-callback-token`**（全小写）。

---

## 2. 出站：创建配送单（本系统 → 聚合）

`webhook` 模式下将 **业务侧传入的 JSON 原样 POST** 到 `DELIVERY_CREATE_WEBHOOK_URL`。

集成中心「主动下发」测试要求 body 中至少包含 **`external_order_id`**（与 `delivery_schedules.external_order_id` 及回调一致）。正式对接时，收件人、坐标、重量等字段名**以聚合商文档为准**，由业务组装进同一 JSON。

---

## 3. 入站：配送状态回调（聚合 → 本系统）

**URL**

```http
POST /api/delivery-callbacks/status
```

**请求头**

| 头 | 必填 |
|----|------|
| `Content-Type` | 是，`application/json` |
| `x-delivery-callback-token` | 是 |

**Body 字段（核心）**

| 字段 | 必填 | 说明 |
|------|------|------|
| `external_order_id` | 是 | 须能唯一匹配到一条 `delivery_schedules`；若匹配多条返回 409 |
| `provider` | 否 | 建议传聚合平台代号；用于 `deliveryStatusMapping`（如配置里含 `sf`、`meituan` 等规则） |
| `status` / `delivery_status` / `event_type` | 至少其一能表达状态 | 会与 `status_code` / `code` 一起参与映射 |
| `status_code` / `code` | 否 | 数字或字符串；优先走 `PROVIDER_RULES[provider].byCode` |
| `event_id` | 否 | **幂等键**；不传则内部用 `external_order_id:status:delivered_at` 等拼接 |
| `delivered_at` | 否 | 送达时间；映射为 `delivered` 时使用 |
| `rider_name` / `rider_phone` | 否 | 可选同步到排期 |

映射后的内部状态为：`pending` | `scheduled` | `preparing` | `shipped` | `delivered` | `cancelled`。

查询当前映射表（需带令牌）：

```http
GET /api/delivery-callbacks/mapping
```

---

## 4. 回调示例

**文本状态（依赖默认或 provider 规则）**

```json
{
  "provider": "aggregate_city",
  "external_order_id": "DS-20260325-0001",
  "status": "delivered",
  "event_id": "agg-dlv-20260325-001",
  "delivered_at": "2026-03-25T12:30:00.000Z",
  "rider_name": "张师傅",
  "rider_phone": "13800000000"
}
```

**若聚合只给数字状态码**（需在 `deliveryStatusMapping.js` 的 `PROVIDER_RULES` 中为该 `provider` 配置 `byCode`）

```json
{
  "provider": "your_platform_id",
  "external_order_id": "DS-20260325-0001",
  "status_code": 500,
  "event_id": "agg-dlv-20260325-002"
}
```

**成功响应（节选）**

```json
{
  "success": true,
  "deduplicated": false,
  "schedule_id": "uuid-...",
  "normalized_status": "delivered",
  "mapped_by": "provider_text"
}
```

**重复 `event_id`（同 provider）**  
HTTP 200，`deduplicated: true`。

---

## 5. 新增聚合平台时的开发动作

1. 在 `server/config/deliveryStatusMapping.js` 的 `PROVIDER_RULES` 中为该 `provider` 增加 `byCode` / `byText`（与聚合文档一致）。
2. 若聚合回调字段名完全不同，在 **API 网关或 BFF** 层转换为上述 body 再 POST 本系统（避免在业务里散落多种形状）。

---

## 6. 检查清单

- [ ] `external_order_id` 与下发配送单时写入库表的一致
- [ ] `provider` 与映射表中的 key 一致（或依赖默认文本映射）
- [ ] 回调 URL 公网可达，且 HTTPS
- [ ] `x-delivery-callback-token` 与生产密钥一致并轮换策略明确
- [ ] 生产使用 `webhook`/`aggregator`，不用 `mock`

---

## 7. 与「直连顺丰」的关系

`DELIVERY_PROVIDER=sf_city` 为**备选联调**。生产默认应使用本节 **webhook + 回调** 形态对接配送聚合。

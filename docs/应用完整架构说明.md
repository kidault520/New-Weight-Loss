## 2. 技术架构

### 2.1 前端技术栈

```
React 18 + TypeScript
├── 构建工具: Vite
├── 样式方案: Tailwind CSS
├── 状态管理: React Query + Context API
├── 路由管理: 自定义路由（非React Router）
├── 图标库: Lucide React
└── 图表库: Recharts
```

### 2.2 后端技术栈

```
Node.js + Express (可选，主要用于AI功能)
├── 数据库: Supabase (PostgreSQL)
├── 认证: Supabase Auth
├── 实时通信: Supabase Realtime
├── 存储: Supabase Storage
└── AI服务: OpenAI API
```

### 2.3 架构模式

**三层架构（最多3层抽象）**:
```
组件 (Components)
  ↓
Hooks (自定义Hooks，基于React Query)
  ↓
Services (直接操作Supabase)
```

**原则**:
- ❌ 禁止多层抽象（如：组件→Hook→DataManager→Supabase）
- ✅ 最多3层：组件→Hook→Supabase
- ❌ 禁止复杂状态管理（Redux、MobX等）
- ✅ 使用 React Query + Context（仅全局状态）

**架构**: `组件 → Hook → Service → Supabase`

**主要服务**:
```typescript

weightService.ts           // 体重记录CRUD
waterService.ts            // 饮水记录CRUD

sleepService.ts            // 睡眠记录CRUD

// 业务服务

// 用户服务

```

**服务模式**:
```typescript
// 示例：weightService.ts
export const weightService = {
  async getRecords(userId: string) {
    const { data, error } = await supabase
      .from('weight_records')
      .select('*')
      .eq('user_id', userId)
      .order('recorded_at', { ascending: false });
    
    if (error) throw error;
    return data;
  },
  
  async addRecord(userId: string, weight: number) {
    const { data, error } = await supabase
      .from('weight_records')
      .insert({
        user_id: userId,
        value: weight,
        recorded_at: new Date().toISOString()
      });
    
    if (error) throw error;
    return data;
  }
};
```

## 5. 数据流架构

### 5.1 整体数据流

```
用户操作
  ↓
组件 (Component)
  ↓
自定义Hook (use*Query / use*Logic)
  ↓
React Query (缓存、状态管理)
  ↓
Service层 (直接操作)
  ↓
Supabase (数据库)
  ↓
Supabase Realtime (实时推送)
  ↓
React Query (自动更新缓存)
  ↓
Hook (触发更新)
  ↓
组件 (UI更新)
```

### 5.2 数据查询流程

```typescript
// 1. 组件使用Hook
const { data, isLoading } = useWeightRecordsQuery(userId);

// 2. Hook内部使用React Query
export function useWeightRecordsQuery(userId: string) {
  return useQuery({
    queryKey: ['weight-records', userId],
    queryFn: () => weightService.getRecords(userId),
    staleTime: 5 * 60 * 1000, // 5分钟缓存
  });
}

// 3. Service直接查询Supabase
export const weightService = {
  async getRecords(userId: string) {
    const { data, error } = await supabase
      .from('weight_records')
      .select('*')
      .eq('user_id', userId);
    return data;
  }
};
```

### 5.3 数据更新流程

```typescript
// 1. 组件调用Mutation
const addMutation = useMutation({
  mutationFn: (weight: number) => weightService.addRecord(userId, weight),
  onSuccess: () => {
    // 自动使相关查询失效，触发重新获取
    queryClient.invalidateQueries(['weight-records', userId]);
  }
});

// 2. 保存成功后，Supabase Realtime自动推送更新
// 3. React Query监听到更新，自动刷新缓存
```

### 5.4 实时数据同步

**Supabase Realtime机制**:
- 数据库变更 → Realtime推送 → React Query刷新
- 支持多设备同步
- 自动处理冲突

**配置示例**:
```typescript
// Hook中订阅Realtime
useEffect(() => {
  const channel = supabase
    .channel('weight-records')
    .on('postgres_changes', 
      { event: '*', schema: 'public', table: 'weight_records' },
      () => {
        queryClient.invalidateQueries(['weight-records', userId]);
      }
    )
    .subscribe();
  
  return () => {
    supabase.removeChannel(channel);
  };
}, [userId]);
```

### 6.2 数据状态（React Query）

**所有数据查询和缓存由React Query管理**:

```typescript
// React Query配置
const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 5 * 60 * 1000,      // 5分钟缓存
      cacheTime: 10 * 60 * 1000,     // 10分钟保留
      retry: 3,                       // 自动重试3次
      refetchOnWindowFocus: false,    // 窗口聚焦时不自动刷新
    },
  },
});
```

**优势**:
- ✅ 自动缓存管理
- ✅ 自动重试机制
- ✅ 并行查询优化
- ✅ 后台数据刷新
- ✅ 请求去重

## 10. 关键设计原则

### 10.1 架构原则

1. **保持简单**: 避免过度设计，代码易于理解、调试和维护
2. **最多3层抽象**: 组件 → Hook → Supabase
3. **使用React Query**: 不使用Redux，使用React Query管理数据
4. **Context仅用于全局状态**: 仅必要的全局状态使用Context

### 10.2 代码质量原则

1. **函数长度**: 函数≤50行
2. **组件长度**: 组件≤200行
3. **单一职责**: 每个组件/函数只负责一个功能
4. **TypeScript**: 使用TypeScript确保类型安全

### 10.3 性能优化原则

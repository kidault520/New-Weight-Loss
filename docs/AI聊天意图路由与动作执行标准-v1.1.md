# AI聊天意图路由与动作执行标准 v1.3

## 1. 目的

- 统一 AI 聊天处理链路，避免“关键词碰撞导致答非所问”。
- 用“先意图路由，再动作执行”的架构替代分散 if/regex 堆叠。
- 在不确定时先澄清，减少误答与编造。

## 2. 总体架构（四层）

1. 意图路由（Intent Router）
2. 槽位抽取（Slots：日期、餐次、对象）
3. 动作执行（Handler：查配送、查餐食、查补剂、查档案等）
4. 回复生成（受约束模板/LLM）

约束：
- Handler 只输出事实，不做自由补全。
- 回复层不得越权添加事实。

## 3. v1.1 意图集合

- `delivery_address`：配送地址/送到哪里
- `meal_plan`：吃什么/菜品/营养/热量
- `supplement_plan`：补剂吃什么/第几天/疗程
- `report_history`：历史报告/第几份报告
- `profile_fact`：BMI/BMR/身高体重年龄等单事实
- `daily_brief`：今日汇总/日报/整体情况
- `analysis`：分析/建议/风险解释
- `general`：通用闲聊或未命中

## 4. 优先级（冲突时）

`delivery_address` > `supplement_plan` > `meal_plan` > `report_history` > `profile_fact` > `daily_brief` > `analysis` > `general`

说明：
- 配送与餐食冲突时，若用户明确问“送到哪里”，必须走配送。
- “后天补剂吃什么”中的“吃什么”不得劫持到餐食意图。

## 5. 低置信度澄清规则（v1.1 新增）

触发澄清而非直接执行：

1. 配送与餐食同时命中，且用户没有明确“送到哪里”或“吃什么”动作词
2. 餐食与补剂同时命中，且没有明确对象词
3. 主意图 `general` 且置信度过低（短句）

澄清模板：
- 配送 vs 餐食：  
  `你是想问 1) 送到哪里（配送地址）还是 2) 吃什么（菜品与营养）？`
- 餐食 vs 补剂：  
  `你是想问 1) 餐食计划 还是 2) 补剂计划？`

## 6. 动作执行标准

### 6.1 配送地址
- 今日优先读 `【今日餐食配送】`
- 非今日读 `【服务周期配送计划】`
- 若问具体餐次（如晚餐），只返回该餐次配送信息

### 6.2 餐食计划
- 统一读 `【指定日期餐食计划明细】`
- 输出顺序固定：餐次 -> 菜品 -> 营养 -> 热量 -> 来源
- 文案格式（当前线上）：
  - 标题后空一行
  - `---` 作为浅灰分隔线标记（前端渲染）

### 6.3 补剂计划
- 优先用补剂周期快照
- 明确“第几天/阶段/应服补剂”

### 6.4 档案单事实
- BMI/BMR/目标体重等走后端确定性直出
- 有值即返值，无值即返回固定“暂无数据”模板

## 7. 隐私与安全

- 私密字段（如完整手机号、生日、display id、完整住址）不进入自由生成上下文。
- 展示联系人电话时必须脱敏。

## 8. 观测与回归测试

每次改动至少回归以下用例：

1. `今天晚餐送到哪里` -> 必须返回配送信息，不得返回菜品清单
2. `我明天晚餐会吃什么` -> 返回菜品+营养+热量
3. `我后天补剂吃什么` -> 返回补剂计划，不得返回餐食
4. `我BMI是多少` -> 确定性直出
5. 模糊短句（如“今天晚餐”）-> 先澄清，不直接误答

## 9. 澄清模板可配置（v1.2 新增）

为避免每次改澄清文案都要发版，支持通过环境变量覆盖默认模板：

- 环境变量：`AI_CHAT_INTENT_CLARIFY_TEMPLATES_JSON`
- 作用范围：`delivery_vs_meal`、`meal_vs_supplement`、`low_confidence_general`
- 缺失字段自动回退默认文案
- JSON 非法时自动回退默认文案

示例：

```json
{
  "delivery_vs_meal": "我先确认一下：你要看配送地址，还是看餐食内容？",
  "meal_vs_supplement": "我先确认一下：你是问餐食，还是问补剂？",
  "low_confidence_general": "我先确认一下你想查哪一类：餐食、配送、补剂、档案或报告？"
}
```

## 10. 版本记录

- `v1.0`：建立三大域数据快照规范
- `v1.1`：引入统一 Intent Router、优先级路由、低置信度澄清
- `v1.2`：澄清模板环境变量化（可配文案，无需发版）
- `v1.3`：混合档案问句修复（错拼归一化 + 单事实直出门槛 + 多意图不提前截断）

## 11. 混合档案问句处理规范（v1.3 新增）

### 11.1 适用问题

同一句里混合多个档案事实与建议诉求，例如：
- 当前体重 + 目标体重 + BMI/BMR + “我还需要做什么”
- 含错拼词：`pmi`、`dmr`、`目标启动`

### 11.2 归一化规则

在意图路由前先做消息归一化：
- `pmi` -> `bmi`
- `dmr` -> `bmr`
- `目标启动` -> `目标体重`

### 11.3 确定性直出触发门槛

`档案单事实确定性直出` 仅在以下条件同时满足时触发：
- 主意图是 `profile_fact`
- 仅请求 1 个档案事实（如仅问 BMI）
- 不含建议/规划意图（如“还需要做什么/怎么才能达到目标”）
- 非日简报/非分析场景

否则：不允许提前 `return`，必须进入组合回答流程。

### 11.4 组合回答顺序

混合问句统一按以下顺序回答：
1. 档案事实段（当前体重、目标体重、BMI、BMR）
2. 目标差距/状态段
3. 下一步建议段（可执行动作）

### 11.5 验收用例（新增）

- `我现在的体重是多少目标启动是多少pmi是多少dmr是多少你看我现在还需要做什么才能达到我的目标`
  - 必须同时给出：当前体重、目标体重、BMI、BMR
  - 必须给出建议，不得只返回单一字段
